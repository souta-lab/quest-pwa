# QUEST — 共通テスト学習PWA v0.5.2

共通テストの得点を伸ばすことを目的に、学習履歴から次の単元と難しさを選ぶPWA。基礎の説明と例題→初見問題を自力で解く→別の資料への応用→FSRSの期日復習をつなぐ。React + TypeScript + Vite、Cloudflare Workers + D1 + Queues、ts-fsrs。

v0.5.2「REBELLION」は、赤・黒・白、太い文字、斜線と切り込む形で全画面を再構成。「その評価、覆せ。」を中心に独自の反骨的なコピーを使う。問題面は読みやすく保ち、開始・次問の操作を明確にする。正解、レベルアップ、コンボは短い演出で示す。

出題は、科目内で直近4単元を避ける配分、論点×問い方×題材の組み合わせ履歴、科目に合った8種の題材と10種の問い方で分散する。候補が少ない場合は範囲内で続けられ、期限復習・配点・基礎の優先度は維持する。10-shotの見本は25問から作問IDごとに入れ替える。保存済み問題は予定した論点・問い方・題材に一致するものを再利用し、一致しなければ新しく作るため、以前より生成回数が増える場合がある。数値・変数だけの類題の検出と、同じ単元16問＋同科目の別単元8問を参照する検査で、同型問題を抑える。意味上の類似を完全に判定する仕組みではない。

v0.5では均等ランダム出題・復習1割を、基礎のつながり・最近の成績・配点・復習期限を使う出題へ変更。受験日、目標得点率、1日の時間の目安、科目の配点、数学ⅡBCの選択3項目を設定できる。過去問・模試の実測得点を保存し、AI短問内の正答率と分けて表示する。学習の効果と配分係数は未検証のため、推定得点や偏差値を作らない。

## 起動と新問生成

作問ごとに見本の順序も変えるため、固定した10-shotより入力キャッシュが再利用されにくい場合がある。

Node.js 24以降を使用（ローカル24.19.0、配置PC25.9.0で確認）。

```bash
npm ci
cp .dev.vars.example .dev.vars
# openssl rand -base64 32 で作った値を .dev.vars の ENCRYPTION_KEY に設定
npm run build
npm run db:migrate
npm run dev
```

**http://localhost:8787** を開く。新規登録→開発環境用の確認リンク→パスワードでログイン→科目選択→演習。開発時だけ確認・再設定リンクを画面に表示する。ブラウザはOrigin検証に合わせてlocalhostを使う。

設定画面でOpenAI互換またはAnthropic互換の接続先・生成モデル・APIキーを保存し、「検証モデル」を設定して「その場で新問を作る」を有効にする。生成と検証は同じ接続先・キーを使う。検証モデルを別モデルにでき、同じモデルでも別呼び出しで正解を伏せて解かせる。

初期設定は生成OFF。まずBYOKで運用する実装を選んだ。新問1問につき作問と解答チェックの原則2回、形式修復時は最大3回のAPI利用料金が発生する。1日の生成件数にアプリ側の上限は設けない。日本時間の日付ごとに生成試行数・トークン使用量を記録し、失敗・取り消しも試行として数える。プロバイダーの利用枠・請求も確認する。

解いている間に、生成モードでは次の問題を最大5問までサーバーに保持し、使った分を順次補充する。直後の1問はブラウザにも先読みし、切替時に表示する。5問の準備を始めると、終了後もその分の作問が続く場合がある。待機中はXPブーストの時間を消費しない。JSONの形式不備は1回だけ修復し、独立検証を通してから保存する。通信エラーや解答検証失敗の有料自動再試行は行わない。

## 生成と品質の扱い

- 前提知識、自力正解、単元の間隔、直近の配分、科目の配点、直近60日の計時した過去問成績から優先度を決める。期限復習は通常は新問2問ごと、大きな残量（12問以上）では交互。新問が尽きた保存済みモードは、期限到来済みの復習を続けられる。回答後10分の同一問除外とFSRS期限を守る
- 科目・単元・難度を運営のハーネスで決め、文章・数式だけの4択を生成。想定3分以内で回答の時間制限なし
- 形式・範囲・選択肢・重複を確認し、提案された正解・解説・ヒントを伏せた別呼び出しで解答チェック。正解が一致した問題を保存
- 「AI生成・解答チェック済み・人による校閲なし」と表示。モデルの一致は内容の正しさを保証しない。実モデルでの科目別品質評価は未実施
- 生成問題は共有DBに保存し、運営の承認前は作成者だけが利用できる。BYOKの接続先による自己検証だけでは共有を承認しない。履歴・メモ・APIキーは個人用のまま。正解・解説は回答前のAPIに含めない
- 「問題の詳細」から理由を選び報告すると、報告者の出題・復習・実力評価から即時除外（物理削除せず履歴とXPを保持）。他ユーザーには影響させず、運営の確認材料にする。実際に出題されたユーザーのみ報告でき、重複報告と除外処理を同一トランザクションで保護
- 復習は保存済みの同じ設問で、選択肢の順序だけを変える。復習のためのLLM再生成は不要

`generation_plans`は1アカウントに待機・準備済み・失敗の計画を最大5件保持する。`generation_jobs`に試行回数・モデル・入力/出力トークンを記録する。Queuesの重複配信は状態の条件更新で抑止し、同じジョブで再度LLMを呼ばない。5分を超えた中断は失敗表示にする。応答のない通信失敗では使用量を「不明」として扱う。科目や生成設定が変わった作問は、それ以降の呼び出し・出題を停止する。

現在の単元マップは15科目枠の初期版。全教科・全範囲の網羅性と、生成難度の校正は未完。数学Ⅰ単独・組合せ社会科目・英語以外の外国語などのカタログ追加、リスニング・厳密な図形やグラフは後続対応。

## 残る実装課題

v0.2以降は問題・プロフィール・回答・FSRSカード・現在の問題/メモを別テーブルに保存する。`0002`で旧JSONを移行し、旧`learning_states`は移行バックアップとして残す。旧版へのロールバック時に最新履歴が自動復元される仕組みではない。

更新はプロフィールrevision/操作トークンで競合を検出し、関連行をD1のbatchで保存する。敗れた同時更新は報酬・回答・カードを変更しない。メモとブースト更新は回答履歴を読み書きしない。複数端末の同時メモ編集は後の保存を優先する。

出題は科目を先に抽選し、SQLで候補を選ぶ。1万問のテスト用データでも、従来の次問取得が問題集・全回答を読み込まないことを確認済み。ただし採点・成績・称号の計算はまだ全回答/全カード/自分が参照できる問題集を読み込む。履歴量に比例するため、公開規模に進む前に日別・科目別・単元別の増分集計、保持方針、本番の容量・負荷測定が必要。

AIヒントは本文が正常に届いたときだけ使用扱いにする。通信失敗・無効応答や回答後に遅れて返る回答前ヒントは補助なし評価を保つ。

Material 3 Expressiveの形・色・強弱・動きを採用した独自React UIで、公式コンポーネントの完全な適合監査は未実施。厳密なバネ物理・動的カラーテーマ、アカウント連携・削除、模試記録/校正、管理画面、専門家による教材確認、数式の自動検算、意味上の類題検出、プロンプト版管理、課金額予算は後続対応。

## セキュリティ監査の修正（2026-10-11）

作問は指定した論点を中心に行い、独立した検証者も論点との対応を確認する。参照する直近の設問を最大12問へ拡大し、完全一致と数値だけを変えた同型問題を検出した場合は、既存の1回限りの修正枠で別の設問を作る。新たな課金リトライ枠は増やしていない。直近資料は本人の問題と公開承認済み問題だけを参照する。論点名自体が答えになる場合を考慮し、作問用メタデータは出題APIへ返さない。意味の近い設問すべてを機械的に判別するものではない。

AIへの質問は、3段階ヒントの再作成から会話専用の処理へ分離した。最新の質問へ直接、短い文章で返答する。OpenAI互換・Anthropic互換のストリームを読み、推論部分を除いた返答を文や段落の単位で区切り、正解漏れ・問題との対応・説明の有用性・質問への関連性を検査する。検査は公開済みの全文を含む累積の返信で行い、承認された部分から表示する。未検査の生成トークンを直接画面へ流さない。ストリームを無視して通常JSONで返す互換APIにも対応。1返信は作成1回と確認1〜3回で、通常2〜4回の呼び出しを使う。

質問送信直後の吹き出し、処理状況、確認済みの途中表示、停止、質問例、Ctrl/Command+Enter送信、返信中に入力した下書きの保持を追加。会話を始めると元のヒントは折りたたみ、閉じるボタンを固定表示する。通信切断は完了扱いせず、同一要求を再送して保存済み結果を取得できる。明示的な再作成は新しい要求で行う。停止は上流への通信も中断し、利用者ごとの処理予約を解放する。解答や問題の切替と競合した返信は表示しない。通常の3段階ヒントの成功キャッシュは引き継ぐ。

正解のリング・粒子、XPのカウントアップ、レベルアップ・アイテム・5連続正解・目安達成のバッジ、問題と選択肢の入場、操作ボタンの押下、進捗バーの遷移を追加。操作を待たせる演出は設けず、アプリの動き設定とOSの動きを減らす設定へ対応する。先読み状況、通信切断の案内、版番号を表示する。学習スコア・FSRS・XPブーストの計算は既存の仕組みを使う。
